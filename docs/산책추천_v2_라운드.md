## 1장. 방향

**바뀌는 것:** "캠퍼스를 돌며 경희몬을 잡는 AR 수집 게임" → **"걷고 키우는 산책 동반자 + AI 산책 매칭"**

| | v1 (지금) | v2 |
|---|---|---|
| 경희몬 얻기 | 지도에 저절로 나오는 경희몬을 탭해서 AR 로 잡기 | 걸어서 모은 **티켓으로 뽑기**, 같은 종이 또 나오면 **진화 경험치** |
| 파트너 | 잡은 경희몬 중 하나 | 첫 실행에 C 등급 3마리 중 고름, **함께 걸은 거리로 진화** (0 → 1 → 2단계) |
| 걷기 보상 | 1km 마다 알 1개 (하루 3개) → 부화 | 1km 마다 **티켓 1장** (하루 상한 상수) |
| 산책 추천 | 시간·취향 → AI 코스 | 시간대·계절·날씨·걷기 속도까지 넣은 **추천 v2** + 칼로리 + 식후 걷기 |
| 같이 걷기 | 없음 | **실시간 산책 매칭**: 짝 찾기 → 만남 스팟 → 인상착의 → 스몰토크 → 산책 |
| 산책 뒤 | 없음 | 완료 화면 · 리뷰 · 보상 · **파트너와 AR 사진** |
| 경험치·레벨 | 앱 안에서 계산 | **서버가 계산**, 앱은 받은 값만 표시 |

**그대로 두는 것:** 경희스팟 사진 메모판 (사진·좋아요·앨범·이번 주 대표 사진·카톡 공유), 경희스팟의 공지 탭, 로그인 (카카오 · 경희대 메일 인증 · 닉네임 · 취향 체크리스트).

**끄는 것 (코드는 남김):** 자연 출현 · 탭 잡기 (A), 퀘스트 화면 (B).

**없애는 것:** 알 · 알 게이지 · 부화 로직 (부화 화면은 뽑기 결과 연출로 고쳐 씀).

## 2장. 기능별 내용

### 2-1. 경희몬 v2 · 뽑기 · 진화 (V1)

- **등급:** 24종을 C · B · A · S 로 나눔 (랜드마크 동물은 S 위주). 등급 · 확률표 · 진화 거리 상수는 `CreatureLibrary` 한 곳에 (A).
- **출현 · 포획 끄기:** `GameSystems` 의 스포너를 설정 하나로 끔. 코드 삭제 금지 (A).
- **어울리는 종:** `SpawnConditions` 에서 "지금 시간 · 계절 · 날씨에 어울리는 종의 가중치" 함수를 꺼내 뽑기가 부름 (A → B).
- **티켓:** 1km = 1장, 하루 상한은 상수 (B). 알 시스템은 없애고 **기존 알은 옮기지 않음**.
- **뽑기:** 1장 = C~A, 5장 = B~S. 확률표 보기. 결과 연출은 `HatchScreen` 을 고쳐 재사용 (5장은 한 장씩 넘김). 중복은 그 종의 진화 경험치 (B).
- **진화:** 파트너로 함께 걸은 거리 → 진화 단계. `PartnerBuddy` 가 단계(0~2)를 받아 피규어 크기 (1.0 → 1.15 → 1.3) · 발광 테두리 · 단계 이름을 바꾸고, 단계마다 액세서리 슬롯이 열림 (A). 단계 계산 · 저장은 B.
- **첫 실행:** C 등급 3마리 중 파트너 고르기 (B).
- **도감:** 등급 색 · 진화 단계, 없는 종은 실루엣 (B).
- **저장 이전:** `progress.json` 의 도감 · 파트너 등 기존 데이터는 옮기고, 알 관련 필드는 버림. 레벨 · 경험치는 초기화 (3장 결정).

### 2-2. 산책 추천 v2 (V2)

- **입력:** 걸을 시간 (**15 · 30 · 60분**, 3장 결정), 취향 칩, 지금 위치, 시간대 · 계절 · 날씨 (기상청) · 걷기 속도.
- **점수 (규칙 · AI 공통):** 취향 × 3 + 계절 · 시간 × 2 + 가까움 × 1. `spots.json` 의 소개글 · 태그 사용.
- **AI:** 상위 후보 중에서만 고름. 이유는 소개글 · 태그 · 날씨에 있는 내용만 (응답 검증). 실패하면 규칙 추천.
- **응답:** 장소별 이유 · 거리 · 시간 · 칼로리, "AI 추천 / 기본 추천" 표시.
- **식후 걷기:** 버튼 (점심 · 저녁 시간대 강조) + "일반 건강 정보이며 의료 조언이 아님". 근거 1~2개는 A.
- **스팟 정보 (A):** 경희스팟 25곳에 소개 2~3줄 · 계절 · 시간대 · 실내/실외 (`spots.json`, 필드 이름은 C 와 맞춤).
- **장소 공지:** 산책 길잡이에는 코스 카드의 "공지 N" 과 장소 팝업에만. 목록은 경희스팟 메모판의 공지 탭.

### 2-3. 실시간 산책 매칭 (V3)

- **흐름:** 조건 (30/60분 · 동성만/상관없음) → 대기 (남은 시간 · 취소, 폴링) → 상대 제안 (닉네임 · 공통 취향) → 수락/거절 → 만남 스팟 안내 (지도에 스팟 경희몬) → 인상착의 입력 / 상대 것 보기 → 스몰토크 카드 ("다음 주제") → 산책 시작.
- **짝 찾기 (C):** 구역 → 시간 → 취향 점수, 성별 조건, 차단 · 낮은 별점 제외. 위치는 **건물 단위만**, 산책이 끝나면 삭제.
- **만남 스팟:** A 의 목록 (찾기 쉽고 공개된 곳 8~10곳) 중 두 사람 사이.
- **스몰토크 AI (C):** 공통 취향 + 스팟 + 날씨. 실패하면 A 의 예시 20개.
- **안전:** 신고 · 차단 · 취소, 노쇼 10분 자동 취소, 운영 시간. 인상착의는 `AiModerator` 검사, 상대에게만, 종료 시 삭제.
- **성별:** 로그인 때 **필수 입력** (3장 결정). 상대에게는 보이지 않고 "동성만" 조건에만 씀.
- **시연용 가상 상대 (C):** 설정으로 켜면 대기열에 들어온 사람과 자동 매칭 · 자동 수락.
- **앱 구조 (B):** 인터페이스 + 가짜 구현 (로컬) + HTTP 구현 (Memo 의 Mock/Http 구조와 같게). V0 의 API 명세로 가짜 데이터부터.

### 2-4. 산책 중 · 후 (V4)

- **완료 판정 (C):** 마지막 스팟 도착 또는 거리 80%.
- **완료 화면 (B):** 걸은 거리 · 시간 · 칼로리 · 사진 버튼 (A 의 AR 사진 화면을 엶).
- **파트너와 AR 사진 (A):** `CatchCameraScreen` 에서 잡기 판정 · 점수를 빼고 "파트너와 사진" 모드. AR 지원 폰은 바닥 고정, 아니면 화면 고정. 액세서리 · 진화 단계가 사진에도 보임. 찍은 사진은 앨범에 저장 (`Memo/PhotoCaptureScreen.cs` 흐름 재사용). B 가 부를 화면 여는 함수 하나를 공개.
- **리뷰:** 상대 별점 · 코스 별점 · 한 줄 → 서버 (검사). 상대 별점은 매칭 품질에만 씀.
- **보상 · 경험치 (C):** 서버가 계산 (티켓 · 경험치), 앱은 받은 값만 표시. 경험치 표 제안: 1km 10 · 산책 30 · 함께 60 · 리뷰 10.

### 2-5. 체험 모드 · 개인정보 (V0)

- **체험 모드:** 로그인 화면의 "둘러보기" → 서버가 **체험용 가상 계정**을 만들어 줌 (`/api/auth/guest`, 메일 인증 면제, 닉네임 "체험생-1234" 같은 형식, 일정 기간 뒤 자동 삭제). 사진 · 좋아요 · 매칭까지 **모든 기능**이 됨. 나중에 로그인하면 진행도를 이어받음. 로그인 PR 에 포함, C 리뷰.
- **개인정보 안내 화면:** 성별 · 위치 (건물 단위) · 인상착의의 쓰임과 보관 기간.
