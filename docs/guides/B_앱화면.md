## B-1. 쪽지 좋아요 · 댓글 화면 (R1, 필수)

**목표:** 기획서 "다른 사용자도 그 쪽지를 볼 수 있고 좋아요나 댓글을 통해서 반응을 남길 수 있다."
**완료 기준:** 쪽지에 좋아요를 누르고 취소할 수 있고, 댓글을 쓰고 볼 수 있다. 서버 실패 시 안내가 뜬다.

**지금 코드:** `Memo/MemoBoard.cs`, `Memo/IMemoService.cs`, `Memo/HttpMemoService.cs`, `Memo/MockMemoService.cs`

**🟨 작업자가 결정할 것**
- 댓글 길이 제한, 댓글에 사진 허용 여부
  결정:
- 댓글을 쪽지 상세 안에 펼칠지, 별도 화면으로 갈지
  결정:
- 좋아요를 누른 순간 화면을 먼저 바꿀지(빠름), 서버 응답 후 바꿀지(정확)
  결정:
- 내 쪽지에 반응이 오면 알려 줄지 (알림은 범위가 커짐)
  결정:

**🔗 맞춰야 할 것:** 좋아요·댓글 API 모양 → C 가 `docs/api.md` 에 먼저 추가, 함께 확인. 서버가 준비되기 전에는 `MockMemoService` 에 같은 기능을 넣어 화면부터 진행.

**AI 진행 순서:** "IMemoService 에 좋아요·댓글 메서드를 추가하고 Mock 부터 구현해 주세요" → 화면 → C 의 서버가 나오면 `HttpMemoService` 연결.

## B-4. AI 추천 루트 · 장소 공지 화면 (R2, 필수)

**목표:** C 가 만든 AI 추천과 공지 판별 결과를 지도 위에 보여 줌.
**완료 기준:** 버튼 하나로 추천을 받고, 추천 장소들이 지도에 순서대로 표시된다. 장소를 누르면 그 장소 공지가 원문 링크와 함께 보인다. AI 실패 시에도 화면이 깨지지 않는다.

**🟨 작업자가 결정할 것**
- 추천을 받을 때 사용자에게 무엇을 물을지 (남은 시간만 / 기분·취향도)
  결정:
- 추천 루트 표시 방식 (선 / 번호 핀 / 둘 다), 추천 이유 문장을 어디에 보일지
  결정:
- 응답을 기다리는 동안 보여 줄 화면
  결정:
- 공지를 장소 쪽지판 안에 넣을지, 따로 보일지
  결정:

**🔗 맞춰야 할 것:** 추천 API·공지 API 입력·출력 → C

## B-5. 퀘스트 탭 · 랜드마크 사진 모아 보기 (R3)

**완료 기준:** 퀘스트 목록이 보이고, 조건을 채우면 보상을 받는다. 랜드마크에서 사진들을 모아 보고 대표 사진이 정해진다.

**🟨 작업자가 결정할 것**
- 첫 버전 퀘스트 종류 (예: 처음 가는 랜드마크 방문, 특정 캐릭터 잡기, 쪽지 남기기, 신입생 온보딩 코스)
  결정:
- 퀘스트 갱신 주기 (일일 / 주간 / 고정)
  결정:
- 퀘스트를 앱에 고정할지, 서버에서 내려받을지 (운영 중 바꾸려면 서버)
  결정:
- 대표 사진 기준 (좋아요 수 / 최신 / 기획서 원문은 "가장 인기 많은" — 문구 확인 필요)
  결정:

**🔗 맞춰야 할 것:** 보상 아이템 id → A, 서버형 퀘스트·사진 목록이면 → C
